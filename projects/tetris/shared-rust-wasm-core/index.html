Rust 보드 규칙을 서버와 WebAssembly 클라이언트에서 공유하기

문제 상황​

웹 멀티플레이 테트리스에서는 입력 직후 클라이언트가 블록을 움직이는 동시에 서버도 해당 동작을 처리해야 합니다. 이동 가능 여부와 회전 충돌 판정을 TypeScript와 Rust로 각각 구현하면 한쪽만 수정하거나 경계 조건을 다르게 처리할 가능성이 생깁니다.

보드 규칙을 수정할 때마다 두 언어의 코드를 함께 고치는 대신 같은 판정 코드를 서버와 브라우저에서 사용할 방법을 찾았습니다.

접근 방법 검토​

보드와 블록 판정을 tetris-lib라는 Rust 라이브러리로 분리했습니다. 서버는 이를 직접 사용하고 웹 클라이언트는 브라우저에서 실행할 수 있도록 WebAssembly로 빌드했습니다. 두 환경에서 같아야 하는 이동·회전·충돌 규칙을 공통 코드로 구성했습니다.

구성 요소역할
Board블록 이동·회전·충돌 판정과 줄 제거 등 공용 보드 규칙
JsBoardJavaScript에서 Rust 보드를 호출하도록 연결
TetrisGame서버의 점수와 게임 진행 및 공격·액션 기록 관리
TetrisBoard웹의 입력과 화면 갱신 및 액션 송신 연결

서버와 클라이언트는 같은 판정 코드로 각자의 10×26 크기 보드 상태를 갱신합니다.

해결 과정​

서버용과 웹용으로 나눠 빌드하기​

공용 코어를 두 환경에 맞게 빌드하도록 Rust 라이브러리 형식인 rlib와 WebAssembly 빌드에 사용하는 cdylib를 함께 지정했습니다.

TOML
[lib]
crate-type = ["cdylib", "rlib"]

[features]
default = []
wasm = ["ts-rs", "wasm-bindgen", "serde-wasm-bindgen"]

웹용으로 빌드할 때만 wasm 기능을 켜 JavaScript 연결 코드를 포함했습니다. 서버에서는 이 기능을 끄고 보드 규칙만 사용하도록 했습니다.

이동 판정과 상태 변경을 연결하기​

블록 이동은 이동 가능한지 확인하는 try_move_falling()과 결과를 반영하는 apply_move_falling()으로 나눴습니다. 생성·회전·하강·줄 제거에도 판정과 적용을 나눈 함수를 제공했습니다.

이동 판정에서는 보드를 바꾸지 않고 블록을 구성하는 네 칸이 모두 움직일 수 있는지 확인합니다. 보드 경계나 다른 블록에 막히면 오류를 반환하고 가능하면 현재 위치와 이동할 위치를 담은 계획인 FallingBlockPlan을 반환합니다.

적용 함수는 기존 네 칸을 모두 비운 뒤 이동할 위치를 채웁니다. 한 칸씩 지우고 채우다가 같은 블록의 다른 칸을 덮어쓰지 않도록 했습니다.

서버의 왼쪽 이동은 다음 순서입니다.

RUST
let plan = self
    .board
    .try_move_falling(tetris_lib::MoveDirection::Left)?;
self.board.apply_move_falling(plan);
self.push_action_buffer(TetrisGameActionType::MoveLeft);

웹 쪽도 동일한 판정·적용 순서를 거친 뒤 화면 갱신을 요청하고 멀티플레이 중에는 이동 액션을 서버에 전송합니다.

TypeScript
const b = this.tb.board;
const plan = b.tryMoveFalling("Left");
b.applyMoveFalling(plan);

this.tb.renderHandler.isDirty = true;
if (this.tb.wsSender) {
  this.tb.wsSender.wsSend("moveLeft");
}

JavaScript에서 같은 판정 코드를 호출하기​

wasm-bindgen으로 JsBoard의 생성자와 함수를 JavaScript에서 호출할 수 있도록 했습니다. 실제 판정은 내부의 Rust Board가 처리하고 웹에서 호출하는 이름은 tryMoveFalling처럼 JavaScript 표기에 맞췄습니다.

아래는 Rust로 구현한 JsBoard의 핵심 구조를 TypeScript 클래스 형태로 요약한 예시입니다.

JsBoard의 핵심 구조
class JsBoard {
  private inner: Board;

  tryMoveFalling(direction: MoveDirection) {
    return this.inner.try_move_falling(direction);
  }

  applyMoveFalling(plan: FallingBlockPlan[]) {
    this.inner.apply_move_falling(plan);
  }
}

이동 방향과 이동 계획처럼 구조가 있는 데이터는 serde-wasm-bindgen으로 Rust와 JavaScript 사이에서 변환했습니다. Rust의 판정 결과는 JavaScript 값으로 반환하고 오류는 예외로 전달하도록 연결했습니다.

웹에서 사용할 패키지와 타입 정의 준비하기​

wasm-pack으로 Rust 코드를 WebAssembly와 JavaScript 연결 코드가 담긴 패키지로 만들었습니다. 웹 프로젝트에서는 이 패키지를 라이브러리로 불러 JsBoard를 사용하도록 연결했습니다.

보드와 타일 등의 데이터 구조를 TypeScript에서도 다시 작성하지 않도록 ts-rs로 Rust의 데이터 타입에서 TypeScript 타입 정의를 생성했습니다. 웹에서는 이 정의를 사용해 판정 결과와 보드 데이터를 다뤘습니다.

패키지 빌드와 Rust 테스트 및 생성 파일을 웹 프로젝트에 복사하는 과정은 스크립트로 묶었습니다.

결과​

보드 규칙을 수정할 때 두 언어의 판정 코드를 각각 고치는 대신 Rust 코어를 수정하고 웹용 패키지를 다시 빌드하는 흐름으로 정리했습니다. 공용 코어에는 렌더링과 네트워크 없이 실행할 수 있는 Rust 테스트를 작성해 판정 로직을 확인했습니다.
