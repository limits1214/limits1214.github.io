NvCloth 기반 스키닝 망토 시뮬레이션

문제 상황​

망토는 호그와트 레거시의 분위기와 캐릭터의 인상을 만드는 중요한 요소라고 생각했습니다. 걷거나 빗자루를 탈 때 움직임에 따라 펄럭이는 모습까지 모작에 꼭 담고 싶었습니다.

구현 방법을 찾아보면서 천 시뮬레이션이 필요하다는 것을 알게 됐고 관련 라이브러리로 널리 알려진 NvCloth를 살펴봤습니다. 천의 움직임을 계산하는 기능은 라이브러리를 활용하고 기존 엔진의 애니메이션과 렌더링에 연결하는 방식으로 통합했습니다.

어깨에 붙은 부분은 애니메이션을 따라가고 아래쪽은 중력과 관성 및 바람에 반응해야 했습니다. 다만 화면에 표시하는 망토는 정점이 많아 그대로 물리 계산에 사용하기에는 부담이 컸습니다.

구현 후에는 빗자루로 빠르게 상승하거나 하강할 때 망토가 몸을 뚫거나 캐릭터에서 멀어지고 화면에서 사라지는 문제도 나타났습니다. 계산 비용을 줄이는 것과 함께 빠른 이동에서도 망토가 캐릭터를 따라가도록 조정해야 했습니다.

접근 방법 검토​

물리 계산용 메시와 화면 표시용 메시를 분리했습니다. 정점이 적은 메시로 천의 움직임을 계산하고 그 결과로 기존 망토를 변형해 외형을 유지하면서 계산량을 줄이도록 했습니다.

고속 이동 문제는 충돌체 크기뿐 아니라 부착 위치의 갱신 순서와 이동 관성 및 계산 빈도를 함께 확인하는 방향으로 접근했습니다.

NvCloth에서 제공하는 CPU와 GPU 연산의 부하를 각각 측정했습니다. 대량의 망토를 동시에 시뮬레이션할 필요는 없었으므로 실제 사용 규모에서의 측정 결과를 바탕으로 CPU 연산을 선택했습니다.

해결 과정​

적은 정점으로 계산하고 원래 망토에 반영하기​

CResNvClothMesh에서 두 메시를 같은 본을 기준으로 배치해 서로 대응하는 위치를 찾을 수 있도록 했습니다. 계산용 메시에서는 겹치는 정점을 합치고 정점의 연결 관계와 천이 늘어날 수 있는 범위를 준비했습니다.

여러 망토가 함께 사용할 고정 데이터는 NvCloth의 Fabric으로 관리했습니다. 망토마다 달라지는 정점 위치와 바람·충돌 설정은 개별 Cloth에 담았습니다.

화면용 망토의 각 정점은 계산용 메시의 삼각형 하나에 연결했습니다. 삼각형이 움직일 때 정점이 따라갈 위치를 구할 수 있도록 세 꼭짓점의 반영 비율인 무게중심 좌표를 저장했습니다. 화면용 정점과 계산용 삼각형 표면 사이의 위치 차이도 함께 저장해 원래 망토의 형태를 유지하도록 했습니다.

정점 셰이더에서는 이 정보를 이용해 화면용 정점을 옮겼습니다. 조명이 변형된 표면에 맞게 적용되도록 법선과 접선도 함께 변형했습니다. 같은 변형을 그림자에도 적용하고 망토의 뒷면도 그리도록 했습니다.

Plain Text
CResNvClothMesh: 계산용 메시 준비·화면용 정점과 연결
    ↓
CComNvCloth: 망토별 시뮬레이션 생성·정리
    ↓
CNvClothManager: 천의 움직임 계산·결과 전달
    ↓
정점 셰이더: 고해상도 망토와 그림자에 동일한 변형 적용

CPU에서 계산한 결과는 변경될 때 렌더용 버퍼에 업로드합니다. DX11 경로에서는 GPU에 있는 계산 결과를 셰이더가 직접 읽도록 연결했습니다. 어느 경로를 사용하더라도 화면용 망토에 결과를 반영하는 방식은 같도록 구성했습니다.

어깨는 따라가고 아래쪽은 흔들리도록 연결하기​

계산용 정점마다 영향을 주는 본과 기준 위치를 저장하고 현재 애니메이션에서 따라가야 할 위치를 구했습니다. 어깨 부근은 그 위치에 고정하고 아래쪽은 일정 범위 안에서 움직이도록 했습니다. 처음에는 높이에 따라 움직일 수 있는 범위를 정했으며 이후 정점마다 고정 정도를 지정한 가중치 데이터를 읽어 조절하는 방식도 추가했습니다.

몸의 본에는 구와 캡슐 충돌체를 붙였습니다. 정점이 몸 안쪽으로 움직일 수 있는 범위를 제한하는 Backstop도 함께 적용했습니다. 보행과 빗자루 탑승은 자세가 달라 충돌체 구성을 따로 두었고 빗자루 자체의 충돌체도 추가했습니다.

망토와 충돌체가 이전 프레임의 빗자루 위치를 따라가지 않도록 부착 위치를 계산하는 방식도 조정했습니다. 저장된 최종 변환 대신 빗자루의 현재 위치·회전과 부모 객체의 월드 변환을 조합해 최신 위치를 구했습니다.

Plain Text
게임 객체 FixedUpdate: 애니메이션 기준 부착 위치·충돌체 갱신
    ↓
PhysX 물리 시뮬레이션 → NvCloth 천 시뮬레이션
    ↓
렌더용 파티클 전달 → 망토·그림자 표시

NvCloth는 정점의 현재 위치와 이전 위치의 차이를 이용해 움직이던 방향과 관성을 이어갑니다. 두 위치를 매번 초기화하면 이 차이가 없어져 망토의 흔들림이 끊기므로 평소에는 계산된 위치를 유지했습니다.

처음 생성하거나 순간이동하거나 충돌체 구성이 바뀔 때만 현재 자세에 맞춰 두 위치를 함께 재설정했습니다. 이런 상황에서 이전 움직임을 그대로 이어가 망토가 과도하게 튀는 것을 줄이기 위한 처리입니다.

고속 수직 이동과 사라짐에 대응​

수직 속도와 가속도에 따라 기본 설정과 고속 이동용 설정을 전환했습니다. 설정을 켜고 끄는 기준에 차이를 둬 경계 속도에서 반복 전환되는 일도 줄였습니다.

조정 대상적용 방식
계산 빈도기본 초당 60회에서 급격한 수직 이동 시 120회로 전환
수직 관성급상승·급하강이 망토를 과도하게 끌어당기지 않도록 전달 강도 제한
바람이동 반대 방향으로 부드럽게 바꾸고 최대 강도 제한

CPU 경로에는 계산 결과가 비정상적이거나 망토가 캐릭터에서 지나치게 멀어진 상태가 지속되는지 확인하는 검사를 추가했습니다. 복구가 필요하면 바람과 누적 입력을 정리하고 현재 애니메이션 자세에서 다시 시작하도록 했습니다.

문제를 확인할 때는 충돌체와 계산용 정점을 디버그 형상으로 표시했습니다. Tracy에서는 입력 갱신과 천 계산 및 GPU 업로드 시간을 나눠 확인했습니다. 충돌체의 위치와 크기는 본별로 편집하고 JSON으로 저장할 수 있도록 도구도 구성했습니다.

결과​

기존 망토의 외형을 유지하면서 애니메이션과 천 시뮬레이션을 함께 적용했습니다. 보행과 빗자루 탑승을 같은 시스템에서 처리하고 고속 이동에 필요한 추가 계산은 해당 구간에만 적용하도록 했습니다. 망토가 과도하게 이탈할 때는 현재 자세로 복구하는 경로도 마련했습니다.
