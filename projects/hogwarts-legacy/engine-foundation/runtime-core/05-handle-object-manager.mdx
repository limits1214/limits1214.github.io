# Generation Handle 기반 Object Manager

## 문제 상황

게임 객체는 공격 대상이나 이펙트를 발생시킨 객체처럼 다른 객체를 계속 참조합니다. 포인터를 보관하면 대상이 먼저 파괴된 뒤에도 그 주소가 남는 댕글링 포인터 문제가 생길 수 있습니다. 같은 메모리가 새 객체에 재사용되면 주소만으로는 이전 대상과 새 대상을 구분하기도 어렵습니다.

사용처마다 파괴를 통지하고 참조를 비우는 대신, 접근할 때 대상의 유효성을 공통으로 확인하고 싶었습니다. 또 객체를 갱신하는 도중 삭제하면 순회 중인 컨테이너와 다른 객체의 참조에 영향을 줄 수 있어 실제 정리 시점도 함께 정해야 했습니다.

## 접근 방법 검토

`shared_ptr`도 고려했지만 참조가 남아 파괴가 늦어지거나 서로 참조해 해제되지 않는 상황을 피하고자 했습니다. 게임 객체는 매니저의 `unique_ptr`로 소유하고 다른 객체는 대상을 찾는 식별자인 핸들만 보관하도록 구성했습니다.

접근할 때 대상의 유효성을 확인하고 객체의 수명은 외부 참조와 분리해 관리할 수 있어 이 방식을 선택했습니다.

## 해결 과정

### 슬롯이 재사용돼도 이전 참조를 구분하기

매니저는 객체를 저장하는 칸인 슬롯을 배열로 관리합니다. `CHandle`에는 슬롯의 위치를 나타내는 32비트 인덱스와 같은 슬롯의 이전 객체와 새 객체를 구분하는 32비트 세대 번호를 담았습니다. 두 값을 합친 크기는 8바이트입니다.

```cpp title="Handle.h의 핵심 구성"
class CHandle
{
public:
    constexpr uint32_t GetIndex() const;
    constexpr uint32_t GetGeneration() const;

private:
    uint32_t m_iIndex{ INVALID_INDEX };
    uint32_t m_iGeneration{ INVALID_GENERATION };
};

static_assert(sizeof(CHandle) == sizeof(uint64_t));
```

조회할 때는 인덱스 범위와 객체의 존재 여부를 확인하고 세대 번호를 비교합니다. 조건이 맞으면 객체의 포인터를 반환하고 맞지 않으면 `nullptr`를 반환합니다. 특정 클래스의 객체를 요청하는 `GetGameObjectByHandleT<T>`에서는 `Engine::Cast<T>`로 타입도 확인합니다.

### Free List로 빈 슬롯 재사용하기

객체를 제거할 때 슬롯 벡터에서 해당 원소를 지우면 뒤쪽 인덱스가 바뀌어 기존 핸들이 다른 슬롯을 가리킬 수 있습니다. 따라서 슬롯은 그대로 두고 객체만 정리한 뒤 빈 슬롯의 인덱스를 `m_FreeSlots`에 보관했습니다.

빈 슬롯 목록인 Free List는 `std::vector<size_t>`로 구성했습니다. 객체를 생성할 때 목록 끝의 인덱스를 꺼내 재사용하고 빈 슬롯이 없을 때만 슬롯 배열을 늘립니다. 매번 전체 슬롯에서 빈자리를 찾지 않도록 했습니다.

슬롯을 정리하는 `Reset()`에서 세대 번호를 증가시킨 뒤 Free List에 인덱스를 반환합니다. 재사용 시에는 해당 슬롯의 현재 세대 번호로 새 핸들을 발급합니다.

### 갱신 중 삭제와 실제 메모리 해제를 나누기

삭제 요청은 `PendingDestroy` 표시와 핸들 목록에 기록했습니다. 삭제 예정 객체는 더 이상 갱신하지 않고 실제 정리는 프레임 종료 시 수행했습니다. 정리 도중 다른 객체의 삭제가 요청되더라도 순회 중인 목록이 바뀌지 않도록 새 요청과 현재 처리 목록을 분리했습니다.

객체를 묶는 레이어에도 포인터 대신 핸들 배열을 보관했습니다. 각 슬롯에 소속 레이어를 기록해 삭제 시 해당 레이어만 정리하고 레벨 전환에서는 필요한 레이어만 남기거나 비울 수 있도록 했습니다.

### 실제 사용처에 연결하기

이펙트가 끝난 뒤 실행하는 함수에서는 저장한 포인터를 바로 사용하지 않고 핸들로 대상을 다시 조회했습니다. PhysX의 강체·충돌체도 핸들로 게임 객체와 연결했습니다. 공간 검색 결과에는 즉시 사용할 포인터와 나중에 다시 조회할 핸들을 함께 제공했습니다.

## 결과

외부 참조의 유효성 검사를 매니저의 공통 조회 경로에 모아 사용처마다 파괴 통지와 참조 해제 코드를 반복하는 부담을 줄였습니다. Free List로 빈 슬롯을 재사용하면서도 이전 핸들이 새 객체에 접근하지 않도록 했습니다. 레벨을 정리하거나 이펙트 종료 후 함수를 실행할 때도 핸들로 대상의 유효성을 확인했습니다.
